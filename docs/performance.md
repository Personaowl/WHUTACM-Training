# 性能检查与优化记录

[文档索引](README.md) · [运维](operations.md) · [维护检查清单](todolist.md)

本轮于 2026-10-23 检查当前前后端的数据库访问、外部平台请求、缓存、后台任务和页面加载链路。以下结论基于本地源码与回归测试，没有登录生产服务器，也没有在真实 MySQL 或目标服务器上进行容量压测。

## 本轮改动

| 热点 | 原有开销 | 当前处理与边界 |
| --- | --- | --- |
| 练习抽题 | 每次对全部候选题计算 RAND 并排序 | 改为计数后随机偏移，按 rating、id 读取一题；增加筛选复合索引。保留难度、完整标签 AND 匹配及均匀抽取，不是按 ID 范围碰运气 |
| 练习标签 | 每次进入练习页都读题库标签并拆分去重 | 进程内缓存 60 秒，并发只构建一次；题库同步完成或失败后失效，版本校验防止旧构建覆盖新缓存 |
| 比赛聚合 | 缓存到期时请求线程等待外站，其他读请求也等待刷新 | 有旧快照时立即返回并后台刷新；同一时间只有一轮四平台请求。首次加载仍等待；无快照且全部来源失败时冷却 30 秒，有快照时保留旧数据、30 秒后再试 |
| 题单列表 | 普通 GET 也尝试 INSERT IGNORE 公共题单 | 已存在公共题单时只读；仅缺失时初始化，仍由数据库唯一键防止并发重复创建 |
| 浏览器登录状态 | 每次 API 请求重复解析包含 Base64 头像的整份登录 JSON | 原始存储未变化时复用解析结果，返回用户与令牌副本；仍逐次检查存储变化，跨标签页登录/退出继续生效 |
| 校验轮询与历史展示 | 长时间校验持续每秒查询，离开页面后仍轮询；历史重复分组 | 前几次快速查询，之后退避到 2 秒，后台标签页 5 秒；离开页面中止浏览器请求。历史分组与日期排序仅在数据变化时重算 |

练习抽题仍有 COUNT 和 OFFSET 扫描；标签谓词仍需读取候选标签，**不是常数时间查询**。新索引是否被 MySQL 选用、在实际题库上快多少，需结合执行计划和慢查询验证。每日定时生成的去重选题分支仍保留 RAND，不把低频任务和高频练习请求混为一谈。

赛事旧快照在刷新期间可能不是最新赛程；原响应结构保持不变，不伪造实时性。离开每日题页面只停止浏览器轮询，不撤销服务器已经受理的校验任务；结果仍会记账，返回页面可重新加载。最多查询 60 次状态，最后一次成功也会正常返回；具体总等待时间取决于页面可见性与每次网络耗时。

## 已检查并保留的机制

- **认证与权限**：后端仍按请求检查会话与数据库用户，没有加入延迟生效的认证缓存；超管重置密码后的会话撤销、默认最长 6 小时登录有效期不变。
- **CF 请求**：继续使用统一限速和有界排队；每日题只查最近 30 条提交，不回退全量。后台统计快照不能绕过限速。页面优化不能消除 CF 访问与排队时间。
- **后台任务**：保留校验异步任务、失败冷却、资料快照、受限线程池；不通过盲目增加线程和数据库连接来掩盖等待。
- **首页与看板**：首页公共统计缓存不混入个人积分；训练看板和周训练保持批量读取、内存聚合，不为每位队员分别发起数据库/外站请求。
- **前端与部署**：继续按路由拆分资源；Nginx 的缓存、压缩及限流模板不变。当前仍按单后端实例设计，部分锁、缓存和任务在进程内，不能直接多开实例。

检查涉及认证、每日题/练习、题单/补题、平台绑定与概览、赛事聚合、ABC 同步、周训练、看板/导出，以及前端请求封装、路由加载和主要页面；不是第三方依赖源码或所有可能输入的穷尽证明。

## 本地验证

- 后端完整 verify；新增练习筛选/标签缓存、赛事刷新合并与失败冷却、题单读取不写入等回归用例。
- 40 个并发标签读取只构建一次；40 个赛事缓存到期读取不等待被暂停的外站任务，只调度一轮刷新；首次加载的并发请求共享同一轮来源请求。
- 前端完整测试与构建；覆盖登录状态解析复用、跨标签页变化、防止调用者篡改缓存、轮询退避/取消、成功/失败终止以及第 60 次查询完成的边界。

这些是隔离的正确性与请求合并测试：数据库使用 H2 MySQL 模式，外站使用替身。**不等于真实服务器已通过 40 人并发验收**，也没有据此声称提升百分比或指定服务器必然够用。

## 发布注意

1. 按原流程备份数据库和运行产物，构建并发布前后端，无需新增服务或扩大连接池。
2. 新增索引 `idx_cf_practice_filter (is_interactive, source_contest_id, rating, id)` 由初始化器补齐，不删表、不改积分数据。先在演练库验证；实际建索引可能产生元数据锁或 I/O 开销，应选择低峰发布。
3. 验收练习边界难度/标签、每日题校验、赛事旧数据刷新、题单权限、登录/退出与跨标签页行为。
4. 缓存在进程内，重启后冷加载属正常；外部来源不可用时不要反复重启服务。

## 仍需关注

- **真实容量**：在演练环境逐步提高到约 40 个并发用户，分开测本地页面读取与集中 CF 校验。记录 P50/P95、错误率、CPU、JVM 堆/GC、Hikari 连接等待、数据库慢查询及 CF 队列等待；压测注册、导出和写入时使用测试数据，不能直接打生产账号或冲击外站。
- **历史与题单体积**：每日题历史仍一次获取再前端分页，题单详情仍一次读取全部条目。数据持续增长后优先做服务端分页，保持历史可查询，不通过截断记录“优化”。
- **Excel 导出**：目前仍在内存创建工作簿和结果字节；长日期区间、多管理员同时导出需要单独评估。可按实测引入范围限制、受限并发、流式工作簿或异步导出，避免未经验证地改文件格式/兼容行为。
- **头像**：本轮减少重复 JSON 解析，但头像仍以 Base64 随部分用户响应传输；后续可评估独立图片地址、缓存与缩略图，不应恢复依赖 CF 外链头像。
- **结构演进**：慢 SQL 用真实 MySQL 执行计划确认；需要多实例时，先落实共享任务、分布式锁和全局外站限速，再横向扩容。
